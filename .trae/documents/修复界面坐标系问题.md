## 修复界面坐标系问题的计划

### 1. 实现完善的z分配器

**问题**：当前没有统一的z轴管理机制，不同卡牌和实体之间的遮挡关系处理简单粗糙

**解决方案**：
- 创建 `ZAllocator` 类来统一管理不同实体的z轴位置
- 为不同类型的实体分配不同的z轴范围（靠近相机，防止后方场景遮蔽）：
  - 面板实体：10-19
  - 手牌卡牌：20-29
  - 激活技能：30-39
  - 拖拽中的卡牌：40-49
  - 特效：50-59
  - 图标：60-69
- 实现 `getNextZ()` 方法来获取递增的z值，确保新创建的实体在正确的层级
- 确保所有UI元素的z值在相机近平面和背景之间，防止后方场景影响

### 2. 修复坐标转换算法

**问题**：当前 `screenToWorld` 方法使用简化计算，没有考虑相机的完整投影矩阵，且UI元素Z值固定为0，可能导致与后方场景冲突

**解决方案**：
- 修改 `CoordinateConverter.js` 中的 `screenToWorld` 方法，添加默认Z参数
- 使用 Three.js 内置的 `unproject` 方法进行准确的坐标转换
- 为UI元素设置合适的默认Z值（靠近相机），防止后方场景遮蔽
- 实现：
  ```javascript
  screenToWorld(screenX, screenY, z = 20) {
    const vector = new THREE.Vector3(
      (screenX / window.innerWidth) * 2 - 1,
      -(screenY / window.innerHeight) * 2 + 1,
      0.5
    );
    vector.unproject(this.camera);
    const dir = vector.sub(this.camera.position).normalize();
    const distance = (z - this.camera.position.z) / dir.z;
    return this.camera.position.clone().add(dir.multiplyScalar(distance));
  }
  ```

### 3. 修复卡牌默认scale

**问题**：当前卡牌默认scale被设置为0.5，不符合用户要求的默认值1

**解决方案**：
- 修改 `SceneGraphAdapter.js` 中的 `_createCardEntity` 方法，将默认scale设置为1
- 调整 `_updateCardAnchors` 方法中的布局计算，移除不必要的scale调整
- 更新手牌和激活技能的布局计算，基于正确的卡牌尺寸（198x266像素）
- 调整激活技能的缩放比例，从0.8调整为0.9，以适应新的默认scale
