# 辩证式设计文档审查

这个skill用于对设计文档进行辩证式审查，通过多角度质疑和自我反思来发现设计中的问题、矛盾和模糊之处。

## 核心流程

### 第一步：阅读文档
- 完整阅读目标设计文档
- 理解文档的核心设计理念和目标
- 识别文档中的关键概念、机制和规则
- 记录文档的结构和主要章节

### 第二步：从不同角度质疑文档设计
从以下角度对文档进行质疑：

#### 逻辑一致性角度
- 检查文档内部是否存在逻辑矛盾
- 验证不同机制之间的逻辑关系是否合理
- 检查因果关系是否清晰合理
- 质疑：是否存在自相矛盾的描述？

#### 完整性角度
- 检查是否遗漏了重要的概念或机制
- 验证每个概念是否有充分的定义和解释
- 检查机制描述是否完整，是否有缺失的细节
- 质疑：是否有未定义的术语或未解释的机制？

#### 可实现性角度
- 检查设计是否在技术上可行
- 验证复杂度是否合理
- 检查是否有过于理想化的设计
- 质疑：这个设计是否真的可以实现？

#### 用户体验角度
- 检查设计是否对用户友好
- 验证学习曲线是否合理
- 检查是否有过于复杂的机制
- 质疑：用户能否理解和接受这个设计？

#### 可维护性角度
- 检查设计的代码实现结构是否清晰
- 验证是否有重复、可重用的逻辑，或欠缺与不当的抽象
- 检查是否便于后续扩展
- 质疑：这个设计是否便于长期维护和高效开发？

### 第三步：尝试对质疑给出合理解释，或认可质疑
对于每个提出的质疑：
- 尝试从设计者的角度给出合理的解释
- 分析质疑是否成立
- 如果质疑成立，认可该质疑
- 如果质疑不成立，说明理由
- 记录分析过程和结论

### 第四步：记录质疑，并回到第一步
- 分析这些质疑的严重程度，以及它们和已有被记录质疑的关联性
- 将认可/不认可的新质疑连同其回复记录下来，或者根据他们的内容更新现有记录在案的质疑/回复，进行完善
- 回到第一步，阅读文档，继续尝试新的、不同的质疑
- 直到找不到可以质疑的内容

## 审查输出格式

### 质疑记录
```
质疑编号：[序号]
质疑角度：[角度名称]
质疑内容：[具体质疑]
分析过程：[分析过程]
结论：[认可/不认可]
严重程度：[高/中/低]
改进建议：[具体建议]
```

### 审查总结
```
审查文档：[文档名称]
审查时间：[时间]
质疑总数：[数量]
认可质疑数：[数量]
主要问题：
1. [问题1]
2. [问题2]
...
改进建议：
1. [建议1]
2. [建议2]
...
```

## 审查原则

### 客观性原则
- 基于事实和逻辑进行分析
- 避免主观臆断
- 提供充分的理由支持质疑

### 建设性原则
- 质疑的目的是改进设计
- 提供具体的改进建议
- 避免纯粹的批评

### 全面性原则
- 从多个角度进行审查
- 不遗漏重要的方面
- 考虑各种可能的情况

### 循环改进原则
- 持续进行质疑和改进
- 不满足于表面的审查
- 深入挖掘潜在问题

## 使用示例

### 示例1：审查战斗系统设计
```
第一步：阅读design/combat.md文档
第二步：质疑
  - 质疑1（逻辑一致性）：威能计算公式中，脉位状态提供威能乘区，崩溃状态为3.0，但崩溃状态同时有强烈负面效果，这是否合理？
  - 质疑2（完整性）：文档中没有说明脉位耐久恢复的具体计算公式
第三步：分析
  - 质疑1：反对。崩溃状态的高威能倍率作用于负面效果，正数（高威能倍率）乘以负数（负面效果）为负数，这是一个纯粹的负面效果，而非正负权衡。
  - 质疑2：认可。需要补充脉位耐久恢复的具体计算公式
第四步：记录并继续
  - 记录两个认可/不认可的质疑
  - 继续从其他角度质疑
```

### 示例2：审查游戏机制设计
```
第一步：阅读游戏机制文档
第二步：质疑
  - 质疑1（用户体验）：判定系统使用20面骰子，新手是否容易理解？
  - 质疑2（可实现性）：速度条回合制需要精确的时间管理，实现复杂度是否过高？
第三步：分析
  - 质疑1：不认可。20面骰子是常见的RPG机制，可以通过教程和UI设计帮助新手理解
  - 质疑2：认可。速度条回合制的实现确实比较复杂，需要仔细设计
第四步：记录并继续
  - 记录两个认可/不认可的质疑
  - 继续从其他角度质疑
```

## 注意事项

1. **不要急于下结论**：充分分析后再给出结论
2. **参考之前记录的内容**：不要提出重复质疑，或反复提出不认可的质疑。
3. **保持开放心态**：接受可能的设计缺陷
4. **注重细节**：小问题也可能导致大问题
5. **关注实际应用**：考虑设计在实际游戏中的表现

## 终止条件

当满足以下条件时，可以终止审查：
1. 从所有角度都进行了质疑
2. 找不到新的质疑角度
3. 认可的质疑都已经记录
4. 改进建议都已经提出
